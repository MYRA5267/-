## Что работает частично — и почему

**Threads, Instagram, TikTok — экспорт, а не автопостинг.**
Так и написано в ТЗ (раздел 10): полный Direct Post в TikTok включается
после одобрения `video.publish` и аудита приложения, Instagram зависит от
App Review, Threads — от production-доступа Meta. Модули площадок уже есть
и реализуют общий интерфейс `Connector`; когда доступы выданы, меняется
один файл на площадку, остальная система не трогается.

**Глаз PULSE — векторный, не GLB.**
Все семь состояний на месте и берутся из реальной очереди, а не
проигрываются случайно. Версия на React Three Fiber с Draco-сжатием —
следующий шаг: интерфейс к ней уже готов, состояние приходит одним
значением в `<Eye state={...} />`.

**Голос и медиа в банке идей.**
Сейчас вход текстом. Приём голосовых и файлов через бота — следующий шаг,
таблица `assets` и путь публикации медиа уже есть.

**Автосбор метрик.**
Telegram Bot API не отдаёт просмотры постов канала, поэтому метрики
вводятся руками — и на экране видно, что источник ручной. Автосбор
появится вместе с insights Threads и Instagram.

**Без ключа модели продукт работает.**
`ANTHROPIC_API_KEY` не задан — версии собираются как раскладка идеи по
формату площадки, и приложение прямо говорит: «собрано без модели».
Притворяться моделью нельзя.

## Ещё не начато

Видеоредактор, генерация длинных видео, покупка рекламы, биллинг,
white-label, YouTube Shorts / VK / LinkedIn / Pinterest / X — всё это
за границей первого релиза по разделу 4 ТЗ.

## Что укреплено во втором заходе

Ревью безопасности и ревью кода нашли четырнадцать дефектов. Все закрыты.

### Безопасность

| Что было | Чем это грозило | Как исправлено |
| --- | --- | --- |
| Одобрение по порогу ранга `>= 30` | Редактор по лестнице выше approver'а — то есть мог одобрить собственный текст и отправить его в канал клиента. Гарантия четырёх глаз не работала | Роль названа явно: решают `owner`, `admin`, `approver`. Проверка в политике и в рассылке уведомлений |
| Текст уходил в Telegram с `parse_mode: HTML` без экранирования | Согласующий видел `<a href="…">` буквами и одобрял, а подписчик получал живую ссылку. Одобряли одно — публиковалось другое | Экранируем перед отправкой: в канал уходит ровно одобренное |
| `testAccount` писал статус подключения мимо политики | Viewer мог перевести канал в «нужен доступ» и остановить очередь | Права проверяются явно, до вызова площадки |

### Надёжность

- **Любая угловая скобка в тексте убивала публикацию.** Telegram отвечал 400, это классифицировалось как окончательный отказ, и материал больше не отправлялся. То же экранирование чинит и это.
- **Гонка за `initData`.** Флаг «уже получено» ставился до `await`, поэтому второй одновременный вызов уходил без заголовка и получал 401. Теперь общий промис на всех.
- **Перегенерация с `replace` плодила дубли** вместо замены: уникального ключа не было, старая версия оставалась рядом, а редактор показывал только первую. Теперь ключ `(материал, площадка, формат)`, прошлый текст уходит в историю.
- **Двойное нажатие «Собрать пакет»** запускало две генерации. Теперь материал помечается на время работы — и из этой же отметки глаз показывает состояние «идёт генерация», которое раньше было недостижимо.
- **Правка версии, стоящей в очереди,** доводила задачу до провала с уведомлением «публикация остановлена». Теперь правка снимает публикацию из очереди сразу.
- **Опубликованное можно было переписать** — запись расходилась с тем, что висит в канале. Запрещено.
- **Экспорт-площадки пускались в очередь**, где задача могла закончиться только провалом. Теперь отвечаем понятной ошибкой и предлагаем пакет.
- **Уведомления рассылались внутри открытой транзакции** — по тридцать секунд на получателя при пуле в пять соединений. Перенесены за коммит.
- **Проверка качества вызывала `withUser` изнутри транзакции** — при параллельных запросах пул выедался насмерть. Проверка работает на уже открытом соединении.
- **Ошибки валидации возвращали 500.** Пустой `project`, неверный формат идентификатора, неизвестная площадка — всё это теперь 400 с понятным текстом.
- **Скачивание пакета** не работало в части браузеров: якорь не в документе, ссылка освобождалась в том же такте.
- **Ошибка загрузки редактора** выглядела как вечная «загрузка».
- **Запросы без предела по времени** оставляли экран в состоянии «работаем…» навсегда.

### Что перестало быть мёртвым кодом

`findConflicts` показывает конфликты времени до постановки в очередь.
`approveAll` появился на экране кнопкой «Одобрить всё» по пакету.
История версий читается: в карточке согласования видно, что изменилось.
Отметка о согласованиях появилась в нижней навигации.
`hasBlockers` работает: запрещённая формулировка бренда или превышение
жёсткого предела площадки не пускают материал даже на согласование.

## Как проверить

```bash
npm test                  # 34 теста: статусы, идемпотентность, humanizer, качество,
                          # аналитика, экспорт, экранирование, проверка входных данных
npm run pulse:rls-check   # изоляция арендаторов, роли и право решать — на живой базе
npm run build             # сборка
```

`pulse:rls-check` проверяет в том числе то, что редактор не может одобрить
материал, viewer не решает ничего, а токен площадки не читается даже
владельцем пространства.
