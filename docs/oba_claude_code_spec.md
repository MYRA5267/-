# ОБА — спека для Claude Code

Telegram Mini App для двоих. Один инбокс, напоминания с подстраховкой партнёра, вишлисты с секретным слоем, общий быт.

---

## 0. Что строим

Мультитенантный на уровне «пара»: два человека, одно пространство. Не соцсеть, не команда. Никаких ролей, приглашений по email, настроек прав. Один код-приглашение на связку.

**Приоритет фич — строго по порядку. Не начинай следующую, пока предыдущая не работает end-to-end:**

1. Захват + напоминания + подстраховка партнёра
2. Вишлисты с секретным слоем + разбор ссылок
3. Общий быт
4. Энергия (плотность краски)
5. «Спроси у нас»
6. Отпечаток недели
7. Планировщик «нашего времени» (последним, можно отложить)

Пара: **Гена** — синий слой, **Юля** — розовый.

---

## 1. Стек

- Next.js 14.2 App Router, TypeScript
- Supabase: Postgres + RLS + Realtime
- `grammy` — Telegram-бот, вебхук на `/api/tg/webhook`
- `@telegram-apps/sdk-react` — Mini App SDK
- Claude API (`claude-sonnet-4-6`) — разбор входящей строки
- Vercel Cron — эскалация напоминаний
- Деплой: Vercel

## 2. Авторизация

Только через Telegram `initData`. Проверяй HMAC-подпись серверно (`crypto.createHmac('sha256', ...)` с ключом из bot token) в `lib/telegram/verify.ts` — не доверяй `initData` с клиента. Никаких паролей, email, OAuth.

Первый вход создаёт `couple` и код приглашения из 6 символов. Второй человек вводит код — связка закрыта навсегда, третьего быть не может.

## 3. Схема БД

```sql
couples(id uuid pk, invite_code text unique, created_at timestamptz)

users(id uuid pk, tg_id bigint unique, couple_id uuid fk,
      display_name text, ink text check (ink in ('blue','pink')))

items(id uuid pk, couple_id uuid fk, author_id uuid fk,
      owner_id uuid null,              -- null = общее
      type text check (type in ('task','wish','home','date')),
      text text, note text,
      due_at timestamptz null,
      done boolean default false,
      escalated_at timestamptz null,   -- когда напарнику ушёл пинг
      claimed_by uuid null,            -- СЕКРЕТ: кто берёт желание
      secret_owner uuid null,          -- СЕКРЕТ: пункт видит только он
      url text null, price text null, image_url text null,
      raw_input text,                  -- что человек написал дословно
      embedding vector(1536) null,     -- для «Спроси у нас»
      created_at timestamptz)

energy(id uuid pk, couple_id uuid fk, user_id uuid fk,
       day date, level smallint check (level between 1 and 3),
       unique(user_id, day))
```

**RLS обязательно.** Политика: `couple_id = (select couple_id from users where tg_id = current_setting('app.tg_id')::bigint)`. Прогони `supabase db lint` и Supabase advisors перед мержем.

**Критично про `secret_owner`:** это не UI-фильтр, это уровень БД. Добавь в RLS-политику на `items` условие `(secret_owner is null or secret_owner = current_user_id)`. Тогда секретный пункт физически не выйдет из Postgres к партнёру — ни через список, ни через поиск, ни через cron-уведомления, ни через отпечаток недели. Проверять надо один раз в политике, а не в каждом запросе.

**Критично про `claimed_by`:** это поле НИКОГДА не уходит на клиент партнёра. Не фильтруй в React — фильтруй в SQL-вью или в серверном экшене. Вью `items_visible` отдаёт `claimed_by` только если `claimed_by = current_user_id`, иначе `null`. Утечка этого поля ломает весь смысл фичи.

## 4. Захват — главный экран

Одно поле ввода, одна строка, никаких форм и категорий на входе. Также принимай голосовые в боте (Telegram `voice` → скачать файл → транскрипт → тот же пайплайн).

Серверный экшен шлёт строку в Claude API с системным промптом: вернуть строго JSON, без преамбулы и без ``` — `{type, text, note, due_at, owner}`. Разбирай относительные сроки («завтра в 3», «в пятницу») с учётом `Europe/Amsterdam`. Ответ парсить в try/catch; если JSON битый — фолбэк на тип `task` с сырым текстом. Показывай результат разбора как правку в одну кнопку, а не как модалку с подтверждением.

## 5. Подстраховка партнёра — ядро продукта

Vercel Cron раз в 15 минут:

- `due_at` прошёл, `done = false`, прошло больше 2 часов → бот пишет **напарнику**, а не автору: имя, задача, две кнопки «Напомню лично» / «Возьму на себя». Проставь `escalated_at`.
- Второму человеку повторные уведомления не летят. Никогда. Три пуша подряд одному человеку — это ровно то, из-за чего такие приложения удаляют.
- Никаких стриков, очков, счётчиков пропущенного. Забывчивость не наказывается.

## 6. Вишлисты и секреты

Списки видны обоим всегда. Кнопка «Беру на себя» ставит `claimed_by`. Отметка видна только тому, кто взял. Партнёр не видит ни отметки, ни факта её существования — для него карточка не меняется вообще.

**Ссылка → желание.** Если во входящей строке есть URL, тяни OpenGraph-теги серверно (`og:title`, `og:image`, `og:price:amount`, фолбэк на `<title>`) с таймаутом 5 сек. Не получилось — сохраняй ссылку как есть, без ошибки и без модалки. Домен показывай всегда: человек должен понимать, откуда вещь.

**Сюрприз-режим.** Тумблер «Секрет» рядом с полем ввода. Пункт с `secret_owner` не существует для второго вообще. Визуально — штриховка 45° поверх красочного слоя и лейбл «скрыто от Юли». В боте секретные пункты приходят только в личку автору, никогда в общие сводки.

## 6a. Энергия как плотность краски

Один тап утром: три уровня — «на исходе» / «норма» / «много». Пишется в `energy` на текущий день.

Уровень управляет **непрозрачностью красочного слоя** этого человека во всём интерфейсе (`--o-blue` / `--o-pink`: 0.4 / 0.72 / 1). Когда у Юли слой бледный, Гена это видит, просто открыв приложение, — говорить ничего не надо.

Чего не делать: истории настроений, графиков, «твоя энергия упала на 30%». Уровень живёт один день и сгорает. Никакой аналитики по нему не строим.

## 6b. «Спроси у нас»

Отдельная строка под полем ввода. Запрос → эмбеддинг (`text-embedding` через любой провайдер) → pgvector-поиск по `items` того же `couple_id` → топ-5 в Claude API с задачей ответить одной фразой и сослаться на найденные карточки.

Ответ рендерь как короткий текст + сами карточки, не как чат. Никакой истории диалога. Секреты в выдачу не попадают — это уже гарантировано RLS, дополнительно фильтровать не надо.

## 6c. Отпечаток недели

Воскресенье, 20:00, cron. Постер за неделю: 7 колонок, в каждой два красочных столбика (синий — закрытое Геной, розовый — Юлей), наложение даёт фиолетовый. Ниже — четыре строки в моноширинном: закрыто вместе, каждый сам, перенесли, подстраховали друг друга.

Рендерь серверно в PNG (`@vercel/og` или `satori`) и шли обоим в бота картинкой. Внизу одна фраза от приложения — про то, где вы пересеклись, а не про эффективность.

Запрещено: проценты выполнения, сравнение «кто больше», динамика к прошлой неделе. Это открытка, а не отчёт.

## 7. Визуал: ризограф в два прогона

Референс — файл `oba_miniapp_prototype.html`. Токены и разметку бери оттуда дословно, там уже готовый CSS.

- **Метафора:** каждый партнёр — свой красочный слой. Синий `#0078BF` — один, розовый `#FF48B0` — второй, общее — наложение (`mix-blend-mode: multiply`, даёт `#5E2E86`). Бумага `#E6E4DD`, точечный растр поверх всего.
- **Подпись продукта:** сбитая приводка = забывание. Чем дольше задача просрочена, тем сильнее расходятся красочные слои карточки (`--dx` / `--dy` от 0 до 9px). Просрочку видно боковым зрением, до чтения текста. Не заменяй это на красный цвет или иконку — уйдёт весь смысл.
- **Шрифты:** Alumni Sans 900 (заголовки, капс), Golos Text (интерфейс — кириллица родная), Martian Mono (лейблы, время, служебное). Проверь кириллицу в каждом подключаемом начертании.
- **Акцент:** жёлтый `#FFE800` — только там, где нужно действие человека. Больше нигде.
- Жёсткие рамки 1.5px, радиус 2px, смещённая тень без размытия. Никаких градиентов, стекла, скруглений 16px.
- Тема Telegram НЕ наследуется. Приложение всегда в своей палитре, светлой.

## 8. Чего не делать

- Стриков, ачивок, статистики продуктивности
- Общей ленты активности «кто что сделал»
- Онбординга длиннее одного экрана
- Настроек. Вообще. Если появилась настройка — значит решение не принято.
- Двух режимов ввода. Поле одно.

## 9. Порядок работы

Собери в таком порядке, коммить после каждого пункта:

1. Схема + RLS + проверка `initData` + связка пары по коду
2. Экран «Сегодня», захват без ИИ (всё падает в `task`)
3. Подключить разбор через Claude API
4. Cron + эскалация в бота
5. Вишлисты + вью `items_visible` + разбор ссылок
6. Сюрприз-режим (`secret_owner` в RLS)
7. Быт
8. Энергия
9. «Спроси у нас» (pgvector)
10. Отпечаток недели
11. Визуальный слой по прототипу — последним проходом, целиком

**Тест приватности после пунктов 5, 6, 9 и 10.** Залогинься вторым аккаунтом и убедись, что ни `claimed_by`, ни секретные пункты не приходят в сетевом ответе, не всплывают в поиске и не попадают в счётчики отпечатка недели. Это единственное место в проекте, где баг ломает доверие, а не UX.
